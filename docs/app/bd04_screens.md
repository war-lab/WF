# 基本設計 BD04 画面

更新日：2026-10-27

位置づけ：大画面とスマホの画面の基本設計。画面の一覧と遷移、各画面の要素と操作、行動ごとの入力手順、大画面の配置、演出と効果音、文言の方針を定める。

上位の方針は `WORD_FARM_APP_DESIGN_v0.1.md`（以下、方式設計）の9章を正とする。画面に出す値は BD03 の BoardView と PlayerView から取り、本書では値の型を定義しない。操作の可否は BD01 11章の `legalActions` に従い、拒否の文言は BD01 9章の文言を使う。

## 結論

大画面は8画面、スマホは7画面と2つの重ね表示で構成する。

大画面は「誰が何をしたか」を場の全員に見せる画面で、操作は管理だけを受け持つ。スマホは「自分が何をするか」を入力する画面で、盤面は拠点を置く場面にだけ出す。

英文を宣言する行動は、すべて「選ぶ → 使う物の確認 → 自分で英文を作って声に出す → 宣言を押す」の4段で入力する。確認の画面では英文を伏せ、使う物だけを出す。英文を自分で作ることを、紙で遊ぶときと同じく本人に残すためである（3.5）。

宣言、手番終了、捨て札、準備の拠点の配置の4つは、押し間違えると取り消しが要るため、確認を挟む。

大画面の文字は、55型のテレビを3m離れて見る前提で、本文を32px以上、要の数字と宣言の英文を48px以上とする。根拠は5.2に示す。この大きさで読めるかは確かめておらず、M5（方式設計12章）の実機のテストで確かめる（未検証）。

MVP は効果音だけを鳴らし、紹介動画で使った素材（`video/public/audio/`）を流用する。BGM は M7 以降で扱う（方式設計1.2）。音の素材は、各サイトの規約でアプリの効果音としての利用が許されることを確かめた（8.1）。絵の素材はまだないため、MVPは図形と文字で描く。

プレイヤーの色には、必ず形の記号を添える。色だけで人を見分けさせない。

## 1. 画面の一覧

|---|---|---|
| H01 | 起動 | 大画面のURLを開いた直後 |
| H02 | ロビー | 参加者を集め、席の並びを決める |
| H03 | 準備 | 拠点の配置から、最初の手番の前まで |
| H04 | 対戦 | 最初の手番から、ゲームの終わりまで |

### 1.2 スマホ

| ID | 画面 | 出る時 |
|---|---|---|
| P01 | 参加 | QRコードを読んで開いたとき |
| P02 | 待機 | ロビーの間と、準備で自分の番でない間 |
| P03 | 拠点の配置 | 準備で自分が置く番のとき、対戦中に拠点を足すとき |

| P05 | 行動の確認 | 英文を宣言する行動を選んだあと |
| P06 | 問い | 自分に問いが出ている間。種類の選択（P06a）と捨て札（P06b） |
| P07 | 結果 | ゲームの終わり |

重ね表示は2つある。

| ID | 重ね表示 | 出る時 |
|---|---|---|
| O1 | 再接続中 | 通信が切れている間。操作をすべて止める |
| O2 | 一時停止中 | ホストが一時停止している間。操作をすべて止める |

### 1.3 画面の遷移

```text
大画面
  H01 起動 ──[部屋を開く]──→ H02 ロビー ──[ゲームを始める]──→ H03 準備
  H03 ──[準備の完了]──→ H04 対戦 ──[gameOver]──→ H07 結果 ──→ H08 記録の書き出し
  H03／H04 ──[管理]──→ H05 管理パネル ──[取り消し]──→ H06 取り消しの確認
  H07 ──[もう1局]──→ H02 ロビー（同じ参加者を残す）

スマホ
  P01 参加 ──[ロビーに参加する]──→ P02 待機
  P02 ──[自分が置く番]──→ P03 拠点の配置 ──[ここに置く]──→ P02
  P02 ──[準備の完了]──→ P04 対戦
  P04 ──[英文の行動を選ぶ]──→ P05 行動の確認 ──[宣言／やめる]──→ P04
  P04 ──[拠点を足す]──→ P03 ──→ P05 ──→ P04
  P02／P04 ──[自分への問い]──→ P06 問い ──[答えた]──→ もとの画面
  P04 ──[gameOver]──→ P07 結果
  どこからでも ──[切断]──→ O1　　──[一時停止]──→ O2
```

スマホの画面は、サーバーから届いた表示（BD03）の段階と問いで決める。スマホが自分で画面を進めることはない。再接続の直後に、正しい画面へ戻すためである。

問い（P06）は、ほかのどの画面よりも優先して出す。方式設計9.2のとおりである。

## 2. 大画面の各画面

### 2.1 H01 起動

| 要素 | 内容 |
|---|---|
| ホストの鍵 | ブラウザに鍵が保存されていなければ、入力の欄を出す。入れた鍵は `localStorage` に保存する（BD05 1.2）。鍵がなければ「部屋を開く」を押せない |
| 部屋の一覧 | ホストの鍵で取った部屋の一覧（作成の日時、段階、参加者の数）。続きを遊ぶ部屋を選ぶ（BD05 2.11） |
| ルール設定 | 人数は表示だけ（ロビーで決まる）。注文の山（`orderDeck`：自動生成／印刷用）、サイコロ（`dice`：サーバー／本物）、動物の頭数の注文の指定（`animalInclude`。既定はなし。BD02 6章） |
| 読み込みの表示 | 選んだ部屋につないで状態を受け取るまで、その旨を出す |
| 部屋を開く | 押すと新しい部屋を作り（BD05 2.11）、H02 へ進む。このボタンで音を鳴らせる状態にする（方式設計9.1） |

ルール設定の4項目は、BD03 の `startGame` の options と同じ項目である。H01 で選んだ値を、H02 の「ゲームを始める」で送る。

ブラウザに前回の部屋の ID が保存されていて、その部屋がゲームの途中なら、H02 を飛ばして H03 か H04 へ進み、続きを出す。サーバーは止まらずに動いているため、一時停止にはしない（BD05 2.7）。

部屋がエンジンの版の違いで止まっている場合は（`ENGINE_CHANGED`、BD05 2.10）、記録を作った版と今の版を出し、「記録を作った版に戻してデプロイし直してください。記録はそのまま残っています」と出す。

### 2.2 H02 ロビー

| 要素 | 内容 |
|---|---|
| QRコード | 中央に大きく出す。一辺400px以上。大画面のブラウザで作る（BD05 4.6）。下に「モバイル通信のまま読んでください」と出す |
| 参加者の一覧 | 参加した順に、名前、色と形、接続の状態を出す。3〜4人 |
| 並べ替え | ホストがマウスで並べ替える。見出しに「テーブルを時計回りに並べてください」と出す（BD01 1.1） |
| 上級者の印 | 参加者ごとに、日本語の支払いを2倍にするかを切り替える（BD01 2.3 `japaneseRate`） |
| ゲームを始める | 3人か4人がそろったときだけ押せる |

色と形は参加した順に割り当てる（7.3）。参加者が抜けた場合は、その色と形を空けて、次の参加者に回す。

5人目が参加しようとしたら、スマホ側に「満員です」と出す（3.1）。

ゲームを始めると、エンジンが開始プレイヤーを選ぶ。開始プレイヤーの名前を大きく出してから、H03 へ進む。

### 2.3 H03 準備

H04 と同じ配置を使い、次を変える。

- 中央の産地マップで、今置く人の色と形を強調し、「Aki が拠点を置いています（1個目）」のように出す。
- スマホで選んでいる交点を、確定前から点滅させる。本人は大画面で光った位置を確かめてから、スマホの「ここに置く」を押す（3.3）。大画面を指さしながらスマホで選ぶときの誤りを防ぐためである（方式設計9.2）。
- 注文の欄は「ラウンド3の初めに3枚を表にします」とだけ出す。共同注文の2枚は表にした時点で出し、開始プレイヤーに読み上げを促す（2.4の読み上げの促し）。

準備の問い（2個目の拠点のカード、3人戦の追加の1枚）が出ている間は、下の帯に「Ben がカードを選んでいます」と出す。

### 2.4 H04 対戦

配置は5章で定める。各領域に出す物は次のとおり。

| 領域 | 出す物 |
|---|---|
| 上の帯 | ラウンド、手番の人、段階、サイコロの出目、経過時間、残りの注文の山の枚数、終了の予告 |
| 左の列 | プレイヤーごとの欄（4つ）。点、コイン、手札の枚数、無料券、産物、4区画、拠点の数、接続の状態 |
| 中央 | 産地マップ。タイル、数字、拠点、港 |
| 右の列 | 表の注文3枚、共同注文2枚、銀行の山の残り |
| 下の帯 | 直前の宣言の英文と結果、読み上げの促し、出ている交換の申し出と成立、日本語の支払い |

終了の予告は、`endFlagged` の出来事のあとに「最終ラウンドです（ホストの宣言）」「最終ラウンドです（注文切れ）」と出す。

手番の人の欄は、枠を太くし、背景を明るくする。問いに答えていない人の欄には「選択中」の印を出す。

注文のカードには、英文、易の注文の絵（MVPは産物の名前の札）、ボーナス注文の色、時間切れまでの残りを出す。残りは、数える人の色と形の印を残りの数だけ並べる（方式設計9.1）。

注文の難易度（中、難）は出さない。紙の注文で見分けられるのは、絵のある「易」と、色の違うボーナス注文だけで、中と難は見分けられない。難易度を出すと、条件の型（半ダース、合計、同数）の手がかりになる。

注文の条件と点は出さない（BD02 1章）。届けると宣言したときに一度だけ開き（6章の演出）、不成立なら演出のあとで再び隠す。ルールブック06章の「開いた折り返しは元に戻す」に合わせるためである。

共同注文のカードには、英文と、3行それぞれの点だけを出す。空いている行の産物と数は出さない。どの産物をいくつ出すかを英文から読み解くのが、共同注文の読解だからである（ルールブック08章「読み解く対象は、どの産物をいくつ出すか」）。

埋まった行は、出した人の色と形と、置かれた産物と数を出す。紙でもカードの上に置いた産物は見えるためである。

#### 読み上げの促し

ルールブックは、表にした注文を声に出して読むことを求めている（02章、06章）。次の時に、下の帯に読み上げる人と英文を出し、読み上げを促す。

| 時 | 読み上げる人 | 出す文 |
|---|---|---|
| ラウンド3の初めに3枚を表にした | 開始プレイヤー | Aki さん、新しい注文を読み上げてください（Read the new orders aloud） |
| 達成されて補充した | 手番の人 | 同上 |
| 時間切れで補充した | 次の手番の人 | 同上 |
| 共同注文を表にした（準備、完成、時間切れ） | 準備では開始プレイヤー、完成では手番の人、時間切れでは次の手番の人 | 同上 |

促しは、次の宣言か手番の交代まで出しておく。アプリは読み上げたかを判定しない（方式設計6章）。

### 2.5 H05 管理パネル

上の帯の右端の「管理」から開く。ホストの鍵で管理を許された大画面（`welcome` の `admin: true`）だけに「管理」を出す（方式設計3章）。

| 操作 | 内容 | 確認 |
|---|---|---|
| 一時停止／再開 | 時計を止め、全員の操作を止める | なし |
| 取り消し | H06 へ進む | H06 |
| 代わりに答える | 答えていない問いの一覧から選び、既定の選択で答える | あり |
| 手番を終える | 手番の人の代わりに手番を終える。確認に手番の人の名前を出す | あり |
| 席の再発行 | 席を選ぶと、その席専用のQRコードを出す。読んだ端末からの申請をホストが承認して初めて席が移る（下記） | あり |
| 最終ラウンドにする | このラウンドの最後の人の手番の終わりでゲームを終える（方式設計5.9、BD01 8.5 `callLastRound`）。70分を過ぎたら、場で確かめてから押す | あり |
| ゲームを打ち切る | 今の点で順位を付けて終える（BD01 8.5 `abortGame`） | 2回 |

確認のある操作は、「〜しますか？」の確認を出してから実行する。ゲームを打ち切る操作は取り返しがつかないため、2回確認する。

「手番を終える」は、確認を出した時点の手番の通し番号を付けて `endTurnFor(turnSerial)` を送る（BD01 8.5）。確認の間に手番が移っていれば `STALE_TARGET` で拒否され、「表示が古くなっていました。もう一度確かめてください」と出す。古い表示のまま押して、次の人の手番を終えてしまうのを防ぐためである。

#### 席の再発行の手順

席の再発行のQRコードは大画面に映るため、ほかの参加者も読めてしまう。そこで、読んだだけでは席が移らない2段階にする。

1. ホストが席を選ぶと、その席専用のQRコードを出す。QRコードは、1回読まれるか5分たつと消す（BD05）。
2. 読んだ端末に「Aki の席に戻りますか？」と出し、本人が「戻る」を押すと、申請がサーバーに届く。
3. 大画面に「Aki の席に新しい端末がつながろうとしています。承認しますか？」と出す。ホストが本人に確かめてから「承認」を押すと、席が移り、旧端末の接続は切れる。

### 2.6 H06 取り消しの確認

取り消しの対象と、巻き込まれる操作の一覧を出す（方式設計8.2）。

```text
直前の操作から順に取り消します。

  取り消す操作  ：Aki「I sell three carrots to the cafe.」（ラウンド6）
  一緒に消える操作：Ben 日本語の支払い（単語、1コイン）
                    Chika 交換の申し出（Aki へ）

一緒に消える操作は、本人がやり直してください。
すでに見えた情報（開いた注文の条件など）は、見えたままになります。

        [ 取り消す ]   [ やめる ]
```

一覧の各行は、誰が、何をしたかを、下の帯と同じ言い方で出す。

一時停止と再開の記録は、取り消しの対象にせず、一覧にも出さない（BD05）。これらを巻き戻すと、時計とゲームの一時停止の状態が食い違うためである。取り消したら、下の帯に「ホストが1つ前の操作を取り消しました」と出し、全員のスマホにも同じ文を出す。

### 2.7 H07 結果

| 要素 | 内容 |
|---|---|
| 勝者 | 8点到達なら勝者の名前を大きく出す。注文切れか最終ラウンドの宣言なら1位の名前（同順位なら全員） |
| 終わり方 | 8点到達、注文切れ、最終ラウンドの宣言、打ち切りのどれか |
| 順位の表 | 順位、名前、点、コイン。同点はコインで並べ、それも同じなら同順位（BD01 10.2） |
| 点の内訳 | 人ごとに、通常の注文、ボーナス注文、共同注文の行、完成の0.5点、半分の点（BD01 2.3 `ledger`） |
| 開いた注文 | 表に残っていた注文の条件をすべて開く（方式設計5.11） |
| クレジット | 使った音の素材の出典。魔王魂の素材は表記が必要なため必ず出す（8.1） |
| 操作 | 記録の書き出し（H08）、もう1局（H02） |

### 2.8 H08 記録の書き出し

方式設計10章の集計を表で出し、JSON と CSV をまとめた zip をホストPCにダウンロードさせる。記録の取り出しと集計は、BD05 5.1 の手順で、このブラウザの中で行う。

| 要素 | 内容 |
|---|---|
| 集計の表 | 1局の時間、手番の時間の平均と最長、日本語の支払いの回数、不成立の回数、交換の回数など |
| 記録を保存 | 押すと zip をダウンロードさせる。ファイル名は `wordfarm_<開始の日時>.zip` とする |
| 部屋を削除 | 記録を保存したあとに押せる。2回確認する。削除すると記録はサーバーから消え、戻せない（BD05 2.11） |

## 3. スマホの各画面

### 3.1 P01 参加

| 要素 | 内容 |
|---|---|
| 名前 | 1〜12文字（BD03）。前回の名前を `localStorage` から入れておく。欄の下に「あだ名で入ってください（名前は外部のサーバーに保存されます）」と出す（BD05 2.6） |
| 参加する | 押すとロビーに参加し、P02 へ進む。席は、ホストが並べたあと、ゲームの作成時に決まる（BD01 1.1） |

次の場合は、参加の代わりに理由を出す。

| 状況 | 出す文 |
|---|---|
| 部屋が見つからない（`ROOM`） | 部屋が見つかりません。大画面のQRコードを読み直してください |
| 4人そろっている | 満員です |
| ゲームが始まっている | ゲームは始まっています。席を戻すときはホストに伝えてください |

保存したトークンがあれば、名前を聞かずに席へ戻る（方式設計7.4）。

### 3.2 P02 待機

ロビーの間は、自分の名前、色と形、参加者の一覧、「ホストがゲームを始めるのを待っています」を出す。

準備の間は、今置いている人の名前と、「大画面を見てください」を出す。

注文の読み方や交渉の英文の例を、待ち時間に読めるように下に出す（3.10）。

### 3.3 P03 拠点の配置

スマホで産地マップを出す、唯一の画面である。

| 要素 | 内容 |
|---|---|
| 産地マップ | 画面の幅いっぱいに出す。置ける交点だけを丸で示す |
| 選んだ交点 | 拡大して、接するタイルの種類と数字、港なら港の種類を出す |
| ここに置く | 準備では、押すと確認（「この交点に置きます」と接するタイルの一覧）を出し、もう一度押して置く。対戦中に拠点を足すときは P05 へ進む |

置ける交点は、BD03 に載る候補をそのまま使う。スマホで距離ルールを計算しない（方式設計5.1）。

交点は小さいため、タップした位置に最も近い置ける交点を選ぶ。選んだ交点は大画面でも点滅させる（2.3）。

幅360pxに5枚並べると、隣り合う交点の間隔は約42pxで、押せる大きさの目安44px（7.2）を下回る。そのため、選ぶ操作と置く操作を分け、大画面で光った位置を確かめてから置かせる。地図は2本指で拡大できるようにする。

### 3.4 P04 対戦

画面の上から順に、次を置く。

| 位置 | 高さ | 内容 |
|---|---|---|
| 上の帯 | 56px | 手番の人と段階、自分の点とコイン、「日本語」のボタン |
| 本文 | 残り | 選んだタブの中身 |
| 押しボタンの帯 | 64px | 自分の手番：サイコロを振る、手番終了。それ以外は出さない |
| タブの帯 | 56px | 手札、農場、注文、交換 |

自分の手番になったら、上の帯を手番の色にし、「あなたの番です」と出す。振動は補助として使う（方式設計9.2）。

自分の手番でない間も、どのタブも開ける。行動のボタンは押せない状態で出し、押すと「自分の手番ではありません」と出す。

#### 3.4.1 手札のタブ

単語カード9種類を、行動、作物、動物の3段に並べ、枚数を出す。0枚の種類も薄く出す。

産物5種類、コイン、無料券、点も、このタブに出す。

カードの下に、行動のボタンを並べる。

| ボタン | 押せる時（`legalActions`） | 進む先 |
|---|---|---|
| 植える | `plant` のどれかが押せる | 作物の選択 → P05 |
| 動物を買う | `buyAnimal` のどれかが押せる | 動物の選択 → P05 |
| 市場で売る | `sellProducts` に1つ以上ある | 産物と数の選択 → P05 |
| 拠点を足す | `buildHouse` が押せる | P03 |

押せないボタンは理由を小さく添える（例：grow がありません）。理由は `legalActions` の `reason` を BD01 9章の文言にする。

#### 3.4.2 農場のタブ

4区画を2×2で並べる。区画ごとに中身と、そこでできる行動を出す。

| 区画の中身 | 出す物 | ボタン |
|---|---|---|
| 空き | 「空き」 | なし |
| 作物 | 作物の名前と「次の自分の番に収穫」 | なし |
| ニワトリ | 「ニワトリ」 | 餌をやる（卵2つ）、手放す（1コイン） |
| 牛 | 「牛」 | 餌をやる（ミルク3つ）、手放す（2コイン） |

この手番に餌をやった区画は、餌をやるボタンを押せない状態にし、「この手番は餌をやりました」と添える。

#### 3.4.3 注文のタブ

表の注文3枚と共同注文2枚を、大画面と同じ並びで出す。英文は大画面より小さいため、スマホで読み直せるようにする。難易度は出さない（2.4）。共同注文は、英文と行ごとの点だけを出す（2.4）。

注文ごとに「届ける」のボタンを置く。共同注文はカードごとに「出す」のボタンを置く。

この手番に不成立になった注文は、ボタンを押せない状態にし、「この注文はこの手番には届けられません」と添える。不成立になった注文の条件は、演出のあとは出さない（2.4）。

注文がまだ表になっていない間（ラウンド1と2）は、「ラウンド3の初めに3枚を表にします」と出す。

#### 3.4.4 交換のタブ

| 区分 | 内容 |
|---|---|
| 届いた申し出 | 相手、相手が渡す物、相手が欲しい物、承諾と断るのボタン |
| 出した申し出 | 相手、中身、取り下げのボタン |
| 新しい申し出 | 申し出を作る画面へ（4.12） |
| 銀行 | 4枚で1枚、港、カードを買う、産物を買う（自分の手番だけ） |

手番の人でない人は、相手に手番の人しか選べない（BD01 8.3）。

### 3.5 P05 行動の確認

英文を宣言する行動は、すべてこの画面を通る。

```text
┌────────────────────────────┐
│ 注文を届ける                │
│                            │
│ 届け先： the cafe の注文    │
│ 使う物： sell 1、carrot 3   │
│                            │
│ ┌────────────────────────┐ │
│ │ 英文を自分で作って、      │ │
│ │ 声に出して言ってください  │ │
│ │       [ 英文を見る ]     │ │
│ └────────────────────────┘ │
│                            │
│ [ やめる ]     [ 宣言 ]     │
└────────────────────────────┘
```

| 要素 | 内容 |
|---|---|
| 行動の名前 | 日本語で出す |
| 届け先 | 注文、共同注文、ボーナス注文のときだけ。どの注文に届けるかを出す |
| 使う物 | 使うカード、産物、コイン |
| 英文の欄 | 既定では英文を伏せる。本人が、使う物から英文を作って声に出す |
| 英文を見る | 押すと、BD02 7章で組み上げた英文を24px以上で出す。英文を作れない人のための助け |
| 宣言 | 押すとコマンドを送る。届くまで押せない状態にし、二度押しを防ぐ |
| やめる | 何も送らず P04 に戻る |

英文を伏せるのは、数詞、単位（a bag of、a bottle of）、冠詞、宛先を本人が補う練習を、紙で遊ぶときと同じく残すためである。紙の単語カードは英文の一部しか表さず、残りは本人が口で補う（ルールブック05章）。

「英文を見る」を押したかは、宣言のコマンドに `sentenceShown` として付けて送り、記録に残す（BD03、BD05）。試遊で、英文の助けがどれだけ使われたかを数えるためである。押しても不利にはしない。

宣言を押したら、結果（成立、不成立、拒否）を P04 の上に短く出す。拒否なら BD01 9章の文言を出す。大画面は、宣言の英文を先に出し、約3秒おいてから結果を出す（6章）。

### 3.6 P06 問い

自分への問いが出たら、どの画面にいても全画面で出す。答えるまで閉じない。

#### 3.6.1 P06a 種類の選択

| 要素 | 内容 |
|---|---|
| 見出し | 理由ごとに変える。収入「seed のタイルからカードをもらえます」、Market day「好きなカードを1枚もらえます」、救済「何ももらえなかったので、好きなカードを1枚もらえます」 |
| 選択肢 | 問いの `options` だけを出す。山の残りの枚数を添える |
| 枚数 | `count` が2以上なら「あと2枚選んでください」と出し、同じ種類を2回選べるようにする |
| 決める | 選び終えたら押せる |

答えたあとは「ほかの人の選択を待っています」と、自分の答えと「選び直す」のボタンを出す。全員がそろって処理されるまで、答えを送り直せる（BD01 8.6）。

収入の種類の問いでは、同じ人が前回の収入で選んだ種類を、既定で選んだ状態で出す。本人は「決める」を押すだけで答えられる。自動では答えない。毎回同じ種類を選ぶ人の手間を減らしつつ、選ぶ機会を残すためである。前回の選択がない場合と、その種類の山が尽きている場合は、何も選んでいない状態で出す。

選んだ山が処理の時点で尽きていた場合は、問いが出し直される。そのときは見出しの上に「選んだカードがなくなりました。選び直してください」と出す。

#### 3.6.2 P06b 捨て札

| 要素 | 内容 |
|---|---|
| 見出し | 「Market day：単語カードを3枚捨ててください」 |
| 手札 | 種類ごとに、枚数と、捨てる数を増減するボタン |
| 残り | 「あと1枚」のように、選び終えるまでの残りを出す |
| 捨てる | ちょうどの枚数を選んだときだけ押せる。押すと確認を出す（7.1） |

### 3.7 P07 結果

自分の順位、点、点の内訳を出す。全員の順位は大画面を見る前提で、自分の行だけを強調した短い表にする。

### 3.8 O1 再接続中

画面全体を薄く覆い、「再接続しています」と出す。操作はすべて止める。

10秒たっても戻らない場合は、「同じWi-Fiにつながっているか確かめてください。戻らない場合はホストに伝えてください」と足す。

戻ったら、サーバーから届いた全量の表示で画面を作り直す（方式設計7.1）。

### 3.9 O2 一時停止中

画面全体を薄く覆い、「一時停止中です」と出す。操作はすべて止める。手札とタブは見られるようにする。

### 3.10 待ち時間に読む例文

P02 と、他人の手番の間の手札のタブの下に、折りたたんだ欄を置く。中身はルールブック04章の交渉の例と07章の「聞くのはタダ」の言い方である。

例文の正本はルールブックとし、アプリには写しを置く。ルールブックを直したら、写しも直す。

## 4. 行動ごとの入力手順

各行動の入力を、押す順に示す。どの行動も、送る前の確かめは `legalActions` に従い、最終の判定はサーバーが行う。

### 4.1 植える

1. 手札のタブで「植える」を押す。
2. 作物（carrot、potato、wheat）を選ぶ。押せない作物には理由を出す（例：carrot には feed も要ります）。
3. P05 で、使う物（grow 1、carrot 1、feed 1）から英文（I grow carrots and feed the soil.）を作って言い、宣言する。

区画は選ばない。空いている区画のうち番号の小さいほうに置く（BD01 8.1）。

### 4.2 動物を買う

1. 手札のタブで「動物を買う」を押す。
2. ニワトリか牛を選ぶ。必要な物（buy、chicken、2コイン など）を選択肢に添える。
3. P05 で宣言する。

### 4.3 餌をやる

1. 農場のタブで、区画の「餌をやる」を押す。
2. P05 で宣言する（I feed the cow.）。

### 4.4 動物を手放す

1. 農場のタブで、区画の「手放す」を押す。
2. P05 で宣言する（I sell the chicken.）。

### 4.5 市場で売る

1. 手札のタブで「市場で売る」を押す。
2. 産物を1種類選び、数を選ぶ。数は1から持っている数まで。得るコインを添える。
3. P05 で宣言する（I sell four eggs.）。

### 4.6 注文を届ける

1. 注文のタブで、注文の「届ける」を押す。
2. 出す産物と数を選ぶ。手元にある産物だけを選べる。条件に合うかどうかは示さない（方式設計9.3）。
3. P05 で宣言する。
4. 大画面で条件が開き、成立か不成立かが出る。スマホにも結果を出す。不成立なら、演出のあとで条件を再び隠す（2.4）。

ボーナス注文と動物の頭数の注文は、同じ「届ける」から入るが、手順2が違う（4.7、4.8）。

### 4.7 ボーナス注文

1. 注文のタブで、ボーナス注文の「届ける」を押す。
2. 産物を1種類だけ選び、数を選ぶ。2種類を選ぶ操作はできない（ルールブック10章）。
3. P05 で宣言する（I sell seven eggs to the farmers' market.）。

点とコインの見込みは出さない。受け付ける種類を推し量れてしまうためである。

### 4.8 動物の頭数の注文

1. 注文のタブで、頭数の注文の「届ける」を押す。
2. 選ぶ物はない。自分の動物の頭数を出す。
3. P05 で宣言する（I have three animals.）。sell は使わないことを「使う物：なし」で示す。

sell を持っていなくても「届ける」を押せる（ルールブック05章「sellカード不要」）。押せるかは `legalActions` の `deliver` に従う。

### 4.9 共同注文

1. 注文のタブで、共同注文のカードの「出す」を押す。
2. 出す産物を1種類選び、数を選ぶ。数は1から持っている数まで。どの行に当たるかは示さない。
3. P05 で宣言する（I bring three eggs to the village festival.）。
4. 空いている行と、産物と数がちょうど一致すれば、その行が埋まる。一致しなければ `JOINT_MISMATCH` で受け付けず、sell も産物も失わない（ルールブック06章「行と合わない数や産物を出したときは受け付けない」）。

行の産物と数を画面に出さないのは、英文から読み解くのが共同注文の読解だからである（2.4）。

この手番に共同注文に出した場合は、両方の共同注文のボタンを押せない状態にし、「共同注文はこの手番に出しました」と添える。

### 4.10 拠点を足す

1. 手札のタブで「拠点を足す」を押す。
2. P03 で交点を選ぶ。
3. P05 で宣言する（I build a farmhouse.）。使う物に「5コイン」と出す。

### 4.11 銀行、港、購入

英文の宣言がないため、P05 を通らない。交換のタブの「銀行」から入る。

| 操作 | 手順 |
|---|---|
| 4枚で1枚 | 出す種類（4枚以上ある種類だけ）を選ぶ → もらう種類を選ぶ → 確定 |
| 港 | 自分の拠点がある港を選ぶ → 出す種類（港の種類に合い、必要な枚数がある種類だけ）を選ぶ → もらう種類を選ぶ → 確定 |
| カードを買う | 種類を選ぶ → 確定（5コイン） |
| 産物を買う | 産物を選ぶ → 確定（10か15コイン）。この手番に買ったら押せない |

確定のボタンには、出す物ともらう物を「carrot 4 → feed 1」の形で書く。押す前に中身が見えるため、別の確認は挟まない。

### 4.12 交換の申し出

1. 交換のタブで「新しい申し出」を押す。
2. 相手を選ぶ。手番の人には他の全員を名前のボタンで並べ、1回押して選ぶ。手番でない人は相手が手番の人に限られるため、選ぶ手順を省き、手番の人を選んだ状態で始める。
3. 「渡す」と「欲しい」の2つの欄に、単語カード、産物、コインを品目ごとの＋と−で入れる。渡す欄には自分の持っている品目だけを出し、持っている数までしか増やせない。欲しい欄には全品目を出す。
4. 「送る」を押す。両方の欄に1つ以上ないと押せない（ルールブック04章）。

交換は口頭で合意したあとの確認であり、入力の手数がそのまま交渉の途切れになる（方式設計9.4）。手順2と3を上のように絞るのは、そのためである。1回の申し出は、品目が1〜2種類なら、申し出る側で5〜8回の操作に収まる見込みである（見積もり。実測していない）。交渉が途切れるかは、試遊で交換の回数と手番の時間（方式設計10章）から判断する。

同じ相手に新しい申し出を送ると、前の申し出は置き換わる（BD01 8.3）。

### 4.13 交換への応答

届いた申し出は、どのタブを開いていても、画面の大半を覆う窓で出す。窓には相手の名前、渡すものと受け取るもの、大きな「承諾」と「断る」だけを置く。応答を1回の操作で済ませるためである。

| ボタン | 動き |
|---|---|
| 承諾 | 押すと交換する。持っていない物があれば「持っていない物があります」と出し、申し出は残る |
| 断る | 申し出を消す |

条件を変えたい場合は、口頭で交渉したうえで、新しい申し出を4.12の手順で作って送り返す（方式設計9.4）。届いた申し出の中身を写して返すボタンは作らない。写して返す操作があると、口頭の交渉を経ずに、スマホの往復だけで交換がまとまるためである。

出ている申し出は大画面の下の帯にも出す（6章）。英語の交渉の結果をスマホで確定している様子を、場の全員が見られるようにするためである。

手番が移ると、申し出はすべて消える（BD01 7.5）。消えた申し出の帯も消す。

### 4.14 日本語の支払い

1. 上の帯の「日本語」を押す。
2. 3つから選ぶ：単語を1つ、交渉1件、言ってしまった（方式設計6.2）。
3. 払い方を選ぶ：コインか無料券。言ってしまった場合はコインだけ。倍率が2倍の人には、2倍の額を出す。
4. 「払う」を押す。

手番に関係なく押せるが、交渉と行動の段階でないときは「今はできません」と出す（BD01 8.4）。

### 4.15 手番終了

1. 押しボタンの帯の「手番終了」を押す。
2. 確認を出す（7.1）。
3. 「終える」を押すと手番が移る。

## 5. 大画面の配置

### 5.1 領域の寸法

1920×1080 を基準とし、次の寸法を目安にする。

| 領域 | 位置 | 幅 × 高さ（px） |
|---|---|---|
| 上の帯 | 上端 | 1920 × 80 |
| 左の列（プレイヤーの欄） | 左 | 440 × 880（1人 220） |
| 産地マップ | 中央 | 960 × 880 |
| 右の列（注文） | 右 | 520 × 880 |
| 下の帯 | 下端 | 1920 × 120 |

産地マップは、横に5枚並ぶ段（中段）が幅960pxに収まるように、六角の幅を180px（外接円の半径は約104px）とする。上下の段は4枚で、中段より半枚ずつ内側に寄る（盤面データの座標による）。

右の列は、表の注文3枚（1枚 170px）、共同注文2枚（1枚 160px）、銀行の山の残り（1行 50px）で縦に詰める。注文の英文が長く4行を超える場合は、文字を28pxまで下げて収める。28pxで読めるかは確かめていない（未検証）。

素材仕様書（`art/ASSET_SPEC.md` 4章）の表示サイズは「盤面を横1280ピクセルで描いたとき」を基準にしている。本書の産地マップの幅は960pxで、基準と異なる。素材の生成サイズは表示の2倍を確保しているため、縮めて使う分には足りる。

16:9 以外の画面では、全体を縦横比を保って縮め、余白を背景の色で埋める。

### 5.2 文字の大きさ

55型のテレビ（画面の高さ約68cm）に1080の縦解像度で映すと、1pxは約0.63mmになる。

文字の高さを、見る距離の200分の1以上にすることを目安にする。3m離れた場合は15mmで、約24pxである。日本語の文字の高さは、フォントの大きさの約0.75倍であるため、フォントの大きさは32px以上になる。

200分の1は案内表示で使われる目安の一例で、遊ぶ場所の明るさや見る人の視力で変わる。小さいテレビ（40型、1px 約0.46mm）では、同じ文字が約27%小さく見える。M5 の実機のテストで、テレビの大きさと距離を変えて確かめる（未検証）。

| 用途 | 大きさ |
|---|---|
| 本文（産物の数、手札の枚数、注文の英文） | 32px（最小28px） |
| 名前、注文の行 | 32px |
| 点、サイコロの出目、残りの手番数 | 48px 以上 |
| 下の帯の宣言の英文 | 56px |
| QRコードの下の URL | 40px |

文字は、背景との明るさの比を 4.5:1 以上にする（WCAG 2.1 の AA 基準）。

### 5.3 プレイヤーの欄

```text
┌──────────────────────────────┐
│ ● Aki            4.5点  🪙 6 │  ← 名前、点、コイン（48px）
│ 手札 6枚  無料券 2  拠点 3     │
│ 産物 carrot 3  egg 2  milk 0 … │
│ ┌────┬────┬────┬────┐        │
│ │小麦 │ 牛 │空き│鶏  │        │  ← 4区画
│ └────┴────┴────┴────┘        │
└──────────────────────────────┘
```

コインの印は、MVPでは文字「コイン」で代える。絵文字は端末とフォントで見た目が変わるためである。

接続が切れている人の欄は、全体を薄くし、「切断中」と出す。

## 6. 出来事ごとの演出と効果音

MVP の効果音は `video/public/audio/se/` の素材を、アプリの配信フォルダへ写して使う（出典は `art/sound_licenses.md`）。素材にない場面は音を付けない。規約の確認は8.1に書く。

音は大画面だけで鳴らす。スマホは音を鳴らさない。スマホの音は、マナーモードや音量で届かないことが多く、全員が同じ音を聞くには大画面のほうが確実なためである。

## 7. スマホの作りの前提

### 7.1 誤操作の防止

押し間違えたときにホストの取り消しが要る操作には、確認を挟む。

| 操作 | 確認の出し方 |
|---|---|
| 宣言（P05） | P05 自体が確認の画面。宣言のボタンは右下に置き、やめるのボタンと離す |
| 手番終了 | 「手番を終えますか？ 交換の申し出はすべて消えます」と出し、「終える」を押させる |
| 準備の拠点の配置 | 選んだ交点を大画面で光らせ、「ここに置く」をもう一度押させる（3.3） |
| 捨て札 | 「次のカードを捨てます：grow 1、carrot 2」と出し、「捨てる」を押させる |
| 交換の承諾 | 申し出の中身を承諾のボタンの直上に出す。別の確認は挟まない |

確認を挟まない操作（銀行、購入、交換の承諾）は、ボタンの文字そのものに中身を書いて、押す前に中身が見える形にする。

ボタンは、押してからサーバーの返事が届くまで押せない状態にする。通信が遅いときの二度押しで、同じ操作を2回送らないためである。サーバーも同じ `id` を二度処理しない（方式設計7.3）。

### 7.2 寸法と片手の操作

| 項目 | 前提 |
|---|---|
| 基準の幅 | 360px（CSS の px）。320px でも横にはみ出さないことを確かめる |
| 縦の向き | 縦向きだけを作る。横向きでは「縦向きにしてください」と出す |
| 押せる大きさ | 44×44px 以上（Apple の Human Interface Guidelines の推奨） |
| 文字 | 本文 16px 以上、英文 20px 以上（P05 では 24px 以上） |
| 主な操作の位置 | 画面の下半分。宣言、手番終了、承諾、決めるのボタンは、親指の届く下端に置く |
| 安全な領域 | iPhone の下端の操作の帯と重ならないよう、`env(safe-area-inset-bottom)` の余白を取る |

ピンチでの拡大は止めない。文字を大きくして読みたい人がいるためである。代わりに、ダブルタップで拡大されて誤操作にならないよう、ボタンに `touch-action: manipulation` を付ける。

### 7.3 色と形

プレイヤーの色には、必ず形の記号を添える。

| 色 | 記号 | 色の値の目安 |
|---|---|---|
| 赤 | ●（丸） | #D64545 |
| 青 | ■（四角） | #2F6FD6 |
| 緑 | ▲（三角） | #2E9E5B |
| 黄 | ◆（ひし形） | #E0B000 |

赤と緑は、色覚の型によって見分けにくい。形を添えれば、色が見分けにくい人も、拠点、時間切れの印、共同注文の行で誰の物かを形で見分けられる。

拠点のコマは、色で塗ったうえで形の記号を中に描く。時間切れの残りは、数える人の記号を残りの数だけ並べる。

色の値は仮の値である。大画面とスマホで、明るさの比と見分けやすさを、色覚の見え方を再現する道具（ブラウザの開発ツールの表示の再現機能など）で確かめる（未検証）。

## 8. 文言の方針

| 対象 | 言語と書き方 |
|---|---|
| 画面の案内、ボタン、エラー | 日本語。敬体（です、ます）。短く、1文で言い切る |
| ゲームの英文（注文、共同注文、宣言） | 英語のまま。翻訳を添えない |
| カード、産物、動物の名前 | ボタンと表では英語の名前（grow、carrot）を使う。ルールブックと単語カードの表記に合わせる |
| 行動の名前 | 日本語（植える、餌をやる、市場で売る） |

注文の英文に日本語訳を添えないのは、英文の読解がゲームの中心だからである（ルールブック06章）。ルールの確認は日本語でよい（ルールブック07章）ため、画面の案内は日本語にする。

カードの名前を英語にするのは、交渉で使う言葉（*a carrot card*）と画面の表記をそろえ、英語で言いやすくするためである。

エラーの文言は BD01 9章の表を正とする。本書で新たに加えた文言（3.1の参加の失敗、3.8の再接続）は、BD01 の拒否の理由ではなく、通信層の状態から出す。

### 8.1 クレジットの表示

音の素材のうち、魔王魂の素材（`se/win_jingle.mp3`）は、クレジットの表記が必要である（`art/sound_licenses.md`）。H07 の結果の画面と H01 の起動の画面の下端に、次を出す。

```text
BGM：甘茶の音楽工房　音楽：魔王魂（https://maou.audio/）　効果音：効果音ラボ、Pixabay
```

アプリで効果音として鳴らすことは、各サイトの規約の原文で許されることを確かめた（2026-10-27。サブエージェントが規約のページを読んで要約したもの）。

| 配布サイト | アプリでの利用 | 守ること |
|---|---|---|
| 効果音ラボ | 許される。規約が「アプリに操作音として効果音を組み込む（音源ファイルむき出しでも可）」を再配布にあたらない例に挙げている | 効果音を自由に鳴らせる機能（音を聴かせることが主な目的の機能）を作らない。これは再配布にあたる |
| Pixabay | 許される。ほかの素材と組み合わせた作品の一部として使うことは、単体での配布（Standalone）にあたらない | 素材のファイルを単体で配ったり、一覧で取り出せるようにしたりしない |
| 魔王魂 | 許される。あらゆるジャンルの作品で使える | クレジットが必要で、場所は自由。上の表記で満たす。配信の中の mp3 の URL を文書や画面に書かない |

魔王魂の規約は、アプリに組み込むことが「二次配布」にあたるかを定めていない。あたる場合は、クレジットに加えて魔王魂へのリンクが要る。H07 のクレジットに `https://maou.audio/` を添えて、どちらの解釈でも満たすようにする。
